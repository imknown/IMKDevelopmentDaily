生成一套可复用的编程自动化流程:  
1. 让 用户提供 需求 以及 相关资料,  
   汇总到 原始需求文件里,  
   存放到 项目根目录/tasks/<yyyyMMdd_HHmmss-需求梗概>  
   提交 原始需求文件 到 git  
2. 生成 开发者能直接使用的 需求书,  
   跟用户确认 直到用户满意.  
   将最终的 需求书 提交到 git  
3. 生成 详细设计,  
   要包含技术难点, 哪些改动可能是危险等.  
   跟用户确认 直到用户满意.  
   将最终的 详细设计 提交到 git  
4. 生成 差分任务,  
   跟用户确认 直到用户满意.  
   将最终的 差分任务 提交到 git  
5. 串行执行每个拆分的任务, 然后编译,  
   编译通过之后, 执行 各种 test,  
   Test 通过之后, 开启一个 subagent, 使用更强的模型, 基于最初的需求,  
   验证修改是否业务跑偏, 同时检查 Checklist/AndroidKotlinStyle  
   发现问题 回到 原先的 agent 修改,  
   然后等待用户 最终 review,  
   循环往复, 上述所有 tasks 都 build 和 review 通过之后,  
   将 改动 按照 Task 分组, 逐个 提交到 git  
6. 所有 task 执行完 并且 review 完 之后,  
   生成 修改内容 的报告, 将 报告 提交到 git
