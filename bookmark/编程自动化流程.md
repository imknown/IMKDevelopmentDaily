生成一套可复用的编程自动化流程:  

1. 让 用户提供 需求 以及 相关资料,  
汇总到 原始需求文件里,  
存放到 .kiro/tasks/<yyyyMMdd_HHmmss_T-需求梗概>  
yyyyMMdd_HHmmss_T 为 当前时区 的 系统时间  
提交 原始需求文件 到 git  
 
2. 生成 开发者能直接使用的 需求书,  
跟用户确认 直到用户满意.  
将最终的 需求书 提交到 git  
 
3. 生成 详细设计,  
要包含技术难点, 哪些改动可能是危险等.  
跟用户确认 直到用户满意.  
将最终的 详细设计 提交到 git  
 
4. 生成 差分任务,  
跟用户确认 直到用户满意.  
将最终的 差分任务 提交到 git  
 
5. 执行每个拆分的任务, 然后编译,  
单个任务 编译/test 之后, 修改 提交到 git.  
然后 开启一个 subagent, 使用更强的模型, 基于最初的需求,  
验证 需求是否都完成了, 没有不应该修改的, 同时检查 Checklist/AndroidKotlinStyle,  
(Checklist 是 在线的一个 Excel, 询问用户能否提供, 不能的话则不用管)  
发现问题 subagent 不要修改, 回到 原先的 agent 修改,
然后 修改 提交到 git. 然后再 review. 循环往复.  
知道 subagent 认为没问题了, 交给用户 review.  
用户 review 之后, 继续执行下个任务.  
 
7. 循环往复, 上述所有 tasks 都 build, test 和 review 通过之后,  
生成报告, 报告要包含 核心修改内容/Review 记录等, 然后将 报告 提交到 git
